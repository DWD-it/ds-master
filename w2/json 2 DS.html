Data Structure - Week 2 (Time Complexity)

1. يعني إيه Time Complexity (تعقيد الوقت)؟

  • لما بنكتب كود، مش بنقيس سرعته بالثواني (لأن كمبيوترك غير كمبيوتر زميلك). إحنا بنقيس السرعة بناءً على حجم البيانات (n). لو البيانات زادت، الكود هياخد وقت زيادة قد إيه؟
  • عشان نعبر عن ده، بنستخدم حاجة اسمها Big O Notation (O الكبيرة). دي بتعبر عن أسوأ سيناريو (Worst Case) ممكن الكود يمر بيه.
  • القاعدة الذهبية الأولى: دايماً بنهمل الأرقام الثابتة (Constants) وبناخد أعلى أُس. يعني لو كود وقته 1 + n + n^2، بنقول عليه فوراً O(n^2) لأن لما الـ n تكون بمليون، الواحد والـ n مش هيكون ليهم أي قيمة جنب الـ n تربيع.

2. القواعد الستة لحساب الوقت (The 6 Cases)

أولاً: العمليات الثابتة (Constant Time) - O(1)

  • أي عملية حسابية بسيطة (+, -, *, /) أو تعريف متغير (int x = 5) أو عملية مقارنة (if x > 5) بتاخد وقت ثابت، وبنرمز ليه بـ O(1).
  • حتى لو عندك 100 سطر تعريف متغيرات، برضه هيتلموا في الآخر ويكونوا O(1) لإننا بنهمل الثوابت.
int x = 1;      // 1 unit of time
int y = 2;      // 1 unit of time
int z = x + y;  // 1 unit of time
print(z);       // 1 unit of time
// Total = 4 units -> O(1)

ثانياً: الجمل الشرطية (If-Else)

  • الكمبيوتر هيدخل يا إما في الـ if يا إما في الـ else (مستحيل يدخل الاتنين).
  • بما إننا بنحسب الـ Worst Case (أسوأ حالة)، بناخد الوقت بتاع البلوك الأطول فيهم.
if (n == 0) {
    // statement takes O(1)
} else {
    for (int j = 1; j <= n; j++) {
        // statement executes n times -> O(n)
    }
}
النتيجة: الكود الأطول هو الـ else، يبقى الوقت الكلي = O(n)

ثالثاً: اللوب العادية (Loops)

  • اللوب اللي بتزيد بمقدار ثابت (زي i++ أو i+=2) بتنفذ الكود اللي جواها n من المرات.
  • الوقت بيساوي: عدد لفات اللوب × وقت الكود اللي جواها.
int sum = 0;
for (int i = 1; i <= n; i++) {
    sum = sum + i; // Takes O(1)
}
النتيجة: اللوب بتلف n مرة × الكود بياخد 1 = O(n)

رابعاً: اللوب المتداخلة (Nested Loops)

  • هنا بنضرب عدد لفات اللوب الخارجية في عدد لفات اللوب الداخلية. (n * n = n^2).
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j++) {
        // statement takes O(1)
    }
}
النتيجة: O(n) خارجي × O(n) داخلي = O(n^2)

خامساً: اللوغاريتمات (Logarithmic Time) - الزتونة اللي بتلخبط 🧠

  • ركز هنا يا مهندس: اللوب اللي فيها العداد بينضرب أو بيتقسم (زي i = i * 2 أو i = i / 2) دي مابتلفش n مرة، دي بتلف Log n مرة. ليه؟
  • تخيل إن الـ n = 8. لو بنجمع واحد (i++)، اللوب هتلف 8 مرات.
    لكن لو بنضرب في 2 (i=i*2)، الـ i هتكون قيمها: 1 ثم 2 ثم 4 ثم 8. يعني لفت 3 مرات بس!
  • في الرياضة: 2 أُس كام يساوي 8؟ الإجابة 3. وهي دي فكرة الـ Logarithm الأساس 2 للرقم 8 = 3.
  • لو بنضرب في 3 (i=i*3)، يبقى الـ Time Complexity هو O(log_3 n).
for (int i = 1; i <= n; i = i * 2) {
    print(i);
}
النتيجة: عشان بنضرب في 2، الوقت = O(log n)

3. أمثلة وتريكات من الشيت (التفاصيل المملة)

تريكة رقم 1: معادلة رياضية بدل اللوب

  • في مثال طلب منك تجمع الأرقام من 1 لـ n. لو عملناها بـ for loop هتاخد O(n).
  • لكن لو استخدمنا قانون رياضي: Sum = n * (n + 1) / 2. السطر ده عبارة عن ضرب وقسمة وجمع، يعني عمليات ثابتة!
int sum = n * (n + 1) / 2; // Takes constant time 1
النتيجة: O(1) - وده يثبتلك إن خوارزمية الرياضيات أسرع بكتير من اللوب!

تريكة رقم 2: دمج أكتر من نوع لوب (O(n log n))

  • لو عندك لوب خارجية بتزيد بالجمع (n)، وجواها لوب داخلية بتزيد بالضرب أو القسمة (log n).
for (int i = 0; i < n; i++) {                 // Outer loop: O(n)
    for (int j = 1; j < n; j = j * 3) {     // Inner loop: O(log_3 n)
        print(i + j);
    }
}
النتيجة: بنضربهم في بعض = O(n * log_3 n)

تريكة رقم 3 (وحش الشيت): ثلاث لوبات متداخلة!

  • تعالى نفصص المثال الصعب ده اللي موجود في آخر صفحة في الشيت التاني:
for (int i = n/2; i < n; i++) {              // Loop 1
    for (int k = 1; k < n; k = k * 2) {      // Loop 2
        for (int j = 1; j < n; j = 2 * j) {  // Loop 3
            print(i + j + k);
        }
    }
}
  • اللوب الأولى: بتبدأ من n/2 لحد n وتمشي خطوة خطوة (i++). يعني هتمشي نص مشوار الـ n. الوقت بتاعها n/2 اللي هو برضه بنعتبره O(n) لإننا بنطير الثوابت (المقسوم على 2).
  • اللوب التانية: بتضرب في 2 (k = k * 2). الوقت بتاعها O(log_2 n).
  • اللوب التالتة: بتضرب في 2 (j = 2 * j). الوقت بتاعها O(log_2 n).
  • بما إنهم جوة بعض، بنضرب الأوقات: n * (log n) * (log n)
النتيجة النهائية: O(n (log n)^2)

4. ترتيب الكفاءة (Efficiency Order)

عشان لو جالك سؤال رتب الـ Time Complexity من الأسرع (الأفضل) للبطيء (الأسوأ):

  • 1. O(1) -> Constant (أسرع حاجة، طلقة)
  • 2. O(log n) -> Logarithmic (سريع جداً زي الضرب والقسمة)
  • 3. O(n) -> Linear (عادي، زي اللوب البسيطة)
  • 4. O(n log n) -> (أغلب خوارزميات الترتيب السريعة بتقع هنا)
  • 5. O(n^2) -> Quadratic (بطيء، زي الـ Nested loops)
  • 6. O(2^n) -> Exponential (أسوأ حاجة، الكود هيموت لو الـ n كبرت)
